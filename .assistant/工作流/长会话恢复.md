# 长会话恢复

本文件只汇编现有恢复约定，方便长会话按同一顺序恢复；不新增协议。

## 触发词

1. `继续`
2. `继续刚才的任务`
3. `刚才做到哪里了`
4. `恢复`
5. `恢复一下`
6. `continue`
7. `resume`
8. `what were we doing`

## 读取顺序

1. 先读 `运行时/恢复索引.md`。
2. 立刻做索引一致性检查：
   - 比较 `恢复索引.md` 的 `updated` 时间戳与动态 freshness source set。
   - `当前任务.md` 始终参与 freshness 比较。
   - `中断任务.md` 只有存在实际任务行时才参与比较。
   - 只有当前没有活动任务时，`上次会话.md` 才参与比较。
   - 任一有效源比索引更新时，先由入口 host 刷新索引，再重新读取索引。
3. 若索引信息不足，再读 `运行时/当前任务.md`。
4. 按 `当前任务.md` 里的 `task_id` 读取 `运行时/tasks/<task-id>.md`。
5. 再读 `运行时/中断任务.md`。
6. 最后读 `运行时/上次会话.md`。
7. 如有命名检查点，再补读对应 artifact。

## worker callback 处理路径

1. 先按《任务识别协议》判断是 `resume-current`、`switch-existing`、`new-task` 还是 `inbox-first`。
2. worker 只消费恢复信息，不直接改 `当前任务.md`、`中断任务.md`、`恢复索引.md`。
3. 非入口 host 只允许写 `docs/tasks/<task-id>/*` 与 `运行时/tasks/<task-id>.md`。
4. 需要恢复、切换或新建任务时，worker 通过 stage callback / `team_send_message` 把结论回给 leader。
5. 由当前入口 host 负责刷新共享指针、派生视图与恢复索引。
6. 信息不足时先写 `运行时/收件箱.md`，再由入口 host 决定是否升级为新任务或中断任务。

## 单写者临界场景

1. `当前任务.md` 与 `中断任务.md` 冲突时，以 `当前任务.md` 为主。
2. `中断任务.md` 与 `恢复索引.md` 只是派生视图，不能比共享指针更权威。
3. 从一个未完成任务切到另一个任务前，先写旧任务的 `运行时/tasks/<task-id>.md`。
4. 旧任务仍未完成时，再由入口 host 写 `中断任务.md`。
5. 最后才允许切换 `当前任务.md`。
6. 多端并发或运行时文件冲突时，非入口 host 只上报，不自行修指针文件。
7. 活动任务期间，不要只因为 `上次会话.md` 更新更晚，就把 `恢复索引.md` 判为过期。

## 故障兜底

1. `恢复索引.md` 缺失时，直接读 `当前任务.md`、`运行时/tasks/<task-id>.md`、`中断任务.md`、`上次会话.md`，再由入口 host 重建索引。
2. `当前任务.md` 缺失时，优先检查 `中断任务.md` 与 `上次会话.md`。
3. `当前任务.md` 为空且 `上次会话.md` 显示未收尾时，优先提示从中断任务继续。
4. 仍无法判断时，按 `inbox-first` 处理，先写 `运行时/收件箱.md`。
5. 恢复选项与共享指针不一致时，视为派生视图过期，优先提示入口 host 刷新。

## 恢复回复格式

### 当前主任务

```text
task: ...
progress: ...
next step: ...
```

### 其他中断任务

```text
task: ...
priority: ...
progress: ...
next step: ...
```

### 恢复选项

```text
1. 继续当前主任务
2. 切换到 [P1/P2] ...
3. 按编号切换到其他中断任务
```

## 权威源

1. 安装态 `CLAUDE.md` 的“恢复触发”段：触发词与基础读取顺序。
2. `.assistant/工作流/恢复协议.md`：索引 freshness、补充读取顺序、恢复回复格式。
3. `.assistant/工作流/任务识别协议.md`：`resume-current` / `switch-existing` / `new-task` / `inbox-first` 判定。
4. `.assistant/工作流/共享记忆协议.md`：单写者、非入口 host、共享指针与收件箱降级路径。
5. `.assistant/工作流/写回协议.md`：入口 host 写回、恢复索引刷新、收件箱升级路径。
6. 本文件只按上面五项汇编；触发词与读取顺序以 1-2 为准，任务识别以 3 为准，worker callback / 单写者 / 写回路径以 4-5 为准。
7. 若原协议后续更新，以对应原文为准；本文件不覆盖这些权威源。
