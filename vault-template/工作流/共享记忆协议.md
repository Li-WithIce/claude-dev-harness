# 共享记忆协议

## 目标

让 Claude、Codex、Gemini 共用同一份 Obsidian 记忆，不在各自目录下分叉出第二套运行时状态。

## 共享根目录

- 共享记忆仓库：`{VAULT_PATH}`
- 这是 Claude / Codex / Gemini 的共同真相入口
- 不在 `{CLAUDE_HOME}`、`{CODEX_HOME}`、`{GEMINI_HOME}` 下维护平行的运行时记忆

## 读取模式

### 1. 快速了解工作区

按以下顺序读取：

1. `{VAULT_PATH}\首页.md`
2. `{VAULT_PATH}\配置\系统信息.md`
3. `{VAULT_PATH}\配置\用户偏好.md`
4. `{VAULT_PATH}\配置\工具与组件.md`

### 2. 恢复或继续任务

按以下顺序读取：

1. `{VAULT_PATH}\运行时\恢复索引.md`
2. `{VAULT_PATH}\运行时\当前任务.md`（共享指针）
3. 按共享指针中的 `task_id` 读取 `{VAULT_PATH}\运行时\tasks\<task-id>.md`（任务级详细状态）
4. `{VAULT_PATH}\运行时\中断任务.md`
5. `{VAULT_PATH}\运行时\上次会话.md`

### 3. 查询长期稳定记忆

- 用户偏好只看 `配置\*.md`
- 工具路径与组件状态只看 `配置\工具与组件.md`
- 系统边界与真相源只看 `配置\系统信息.md`
- 待确认的长期记忆候选只看 `运行时\记忆候选.md`
- 历史候选结果只看 `运行时\记忆候选归档.md`
- 当前任务状态不要从 `MEMORY.md`、`配置\*.md`、`配置\引导状态.md` 推断

## 并行写保护

### 单写者模型

共享运行时文件（`当前任务.md`、`中断任务.md`、`上次会话.md`、`恢复索引.md`）采用**单写者模型**：

- **入口 agent（Claude Code）** 是共享运行时的唯一写者
- **Codex / Gemini** 只写任务级文档：任务工作区内的 `docs/<task-id>/*` artifact 和 `运行时/tasks/<task-id>.md`，不直接写共享指针文件
- 并行任务可同时推进，但各自只写自己的 `运行时/tasks/<task-id>.md`
- 新任务、恢复任务与切换任务的判定遵循 `{VAULT_PATH}\工作流\任务识别协议.md`

### 任务级状态隔离

- 每个并行任务的详细运行时状态写到 `运行时/tasks/<task-id>.md`
- 新版任务状态文件至少记录：`schema_version`、`artifact_root`、`primary_artifact`、`artifact_links`
- 这里的 `artifact_root = docs/<task-id>/` 默认指**任务所属工作区**中的 artifact 目录，不要求集中写入 `.assistant/docs/`
- `当前任务.md` 降级为共享指针：只保留当前激活任务的 `task_id`、简短进度、最后更新时间、writer 标识
- `恢复索引.md` 只做派生汇总：从共享指针和任务级状态派生，不承载独立真相
- `中断任务.md` 与其中的恢复选项也属于派生视图；若与共享指针冲突，以共享指针为主

### 写保护机制

- 写共享运行时前先检查 `运行时/runtime.lock.json`
- 锁文件包含：`writer`（agent 标识）、`task_id`、`locked_at`（ISO 时间戳）
- 抢锁失败时：停止自动写入，将待写内容转入 `运行时/收件箱.md` 并标注 `[lock-blocked]`
- 锁超时：超过 30 分钟未释放的锁视为过期，可被安全接管

## 写回规则

- 多步骤任务开始、切换或继续时：更新 `运行时\当前任务.md`（共享指针）+ `运行时\tasks\<task-id>.md`（详细状态）
- 任务被打断、待续或等待反馈时：更新 `运行时\当前任务.md`（共享指针）+ `运行时\tasks\<task-id>.md`（详细状态）+ `运行时\中断任务.md`
- 一个阶段完成并收尾时：更新 `运行时\上次会话.md`；必要时同步 `运行时\tasks\<task-id>.md` 的阶段结果或结束状态
- `当前任务.md`、`中断任务.md`、`上次会话.md` 任一变化后：立即刷新 `运行时\恢复索引.md`
- 发现可能值得提升为长期记忆、但尚未确认的内容时：先写 `运行时\记忆候选.md`
- 已完成提升、已否决或已清理的候选：写入 `运行时\记忆候选归档.md`
- 新事项先进入 `运行时\收件箱.md`，再决定是否升级为任务

## 禁写位置

- 不在 `MEMORY.md` 记录当前任务
- 不在 `配置\*.md` 记录会话级临时状态
- 不在 `配置\引导状态.md` 记录运行时任务
- 不在 agent 自己的 home 目录下写平行的 runtime note

## 长期记忆提升

- 只有跨项目、反复验证过的稳定偏好才允许提升
- 提升前需要用户确认
- 当前任务、中断任务、上次会话不提升为长期偏好
- 具体流程见 `{VAULT_PATH}\工作流\记忆管理协议.md`

## 兼容性优化

- 面向 agent 的关键入口文档优先使用普通 Markdown 结构，少依赖 Obsidian 专有语法
- 关键规则写明确文件名和路径，不只写 wiki link
- `恢复索引.md` 保持低 token、低成本，只做导航，不做独立判断
- 新增共享规则时，优先改这里，再让各 agent 的 skill 或入口文件引用这里
- schema 版本注册表见 `{VAULT_PATH}\配置\schema-versions.md`
- 敏感信息边界见 `{VAULT_PATH}\配置\敏感信息规范.md`
- 可通过 `{REPO_ROOT}\skills\obsidian-memory\scripts\check-shared-memory.ps1 -VaultRoot {VAULT_PATH}` 或 `{REPO_ROOT}\skills\obsidian-memory\scripts\run-memory-health.ps1 -VaultRoot {VAULT_PATH}` 定期检查共享记忆一致性
