# 共享记忆协议

## 目标

让 Claude、Codex 共用同一份 Obsidian 记忆，不在各自目录下分叉出第二套运行时状态。

## 共享根目录

- 共享记忆仓库：`{VAULT_PATH}`
- 这是 Claude / Codex 的共同真相入口
- 不在 `{CLAUDE_HOME}`、`{CODEX_HOME}` 下维护平行的运行时记忆

## 真相源分层

- 4 层真相源映射表的唯一来源：`docs/shared-memory-layers.md`；安装后完整路径为 `{REPO_ROOT}\docs\shared-memory-layers.md`
- `docs/tasks/{task_id}/plan.md` frontmatter `stage/tool` 是 task-stage 唯一真相源
- `.assistant/运行时/` 只承载共享运行时，不承载长期配置判断
- user-level Companion Starter vault 只承载跨项目 `配置/*.md` 与 `工作流/*.md`；任务级 `运行时/` 只能写项目本地 `<workspace>/.assistant/运行时/`

## 读取模式

### 1. 快速了解工作区

按以下顺序读取：

1. `{VAULT_PATH}\首页.md`
2. `{VAULT_PATH}\工作流\项目约定.md`
3. `{VAULT_PATH}\配置\系统信息.md`
4. `{VAULT_PATH}\配置\用户偏好.md`
5. `{VAULT_PATH}\配置\工具与组件.md`

### 2. 恢复或继续任务

按以下顺序读取：

1. 只读 `{VAULT_PATH}\运行时\收件箱.md` 中 open `[writeback-fallback]` 的元数据；status/where-were-we 查询不重放，只有用户明确继续或切换并执行 write-authorized workflow 时才按对应 plan stage 判断 `-SyncOnly`
2. `{VAULT_PATH}\运行时\恢复索引.md`
3. `{VAULT_PATH}\运行时\当前任务.md`（共享指针）
4. 按共享指针中的 `task_id` 读取 `{VAULT_PATH}\运行时\tasks\<task-id>.md`（任务级详细状态）
5. `{VAULT_PATH}\运行时\中断任务.md`
6. `{VAULT_PATH}\运行时\上次会话.md`

### 3. 查询长期稳定记忆

- 用户偏好只看 `配置\*.md`
- 工具路径与组件状态只看 `配置\工具与组件.md`
- 系统边界与真相源只看 `配置\系统信息.md`
- 待确认的长期记忆候选只看 `运行时\记忆候选.md`
- 历史候选结果只看 `运行时\记忆候选归档.md`
- 当前任务状态不要从 `MEMORY.md`、`配置\*.md`、`配置\引导状态.md` 推断

## 并行写保护

### 单写者模型

共享运行时文件（`当前任务.md`、`中断任务.md`、`上次会话.md`、`恢复索引.md`）采用**单写者模型**：

- **当前入口 host** 是共享运行时的唯一写者；它由当前任务的 `entry_tool` 决定
- `entry_host` 是 agent 平台标识（`claudecode | codex | team-leader`）；`entry_tool` 是 backend 标识，二者共同刻画当前唯一共享写者
- **未被选为入口 host 的 Codex** 只有在用户明确开始、继续或切换并执行 write-authorized `mode=workflow` 时，才写任务级文档：任务工作区内的 `docs/tasks/{task_id}/*` artifact 和 `运行时/tasks/<task-id>.md`；read-only inspect/status 零写，也不直接写共享指针文件
- `advance-stage.ps1` 是正常的 canonical runtime writer；Claude hooks 保持 write-free，不能刷新共享指针、task mirror 或恢复索引
- 并行任务可同时推进，但各自只写自己的 `运行时/tasks/<task-id>.md`
- 新任务、恢复任务与切换任务的判定遵循 `{VAULT_PATH}\工作流\任务识别协议.md`

### 任务级状态隔离

- 每个并行任务的详细运行时状态写到 `运行时/tasks/<task-id>.md`
- 新版任务状态文件至少记录：`schema_version`、`artifact_root`、`primary_artifact`、`artifact_links`
- 这里的 `artifact_root = docs/tasks/{task_id}/` 默认指**任务所属工作区**中的 artifact 目录，不要求集中写入 `.assistant/docs/`
- `当前任务.md` 降级为共享指针：只保留当前激活任务的 `task_id`、简短进度、最后更新时间、writer 标识
- `恢复索引.md` 只做派生汇总：仅从共享指针和合法未完成 task mirror 派生，不承载独立真相
- `中断任务.md` 与其中的恢复选项也属于派生视图；若与共享指针冲突，以共享指针为主

### 写保护机制

- 共享运行时只通过 canonical writer / repair / 标准 inbox 脚本写入；这些入口内部使用同一 named mutex 串行化
- `运行时/runtime.lock.json` 仅是 repair 期间的瞬时诊断文件，不是锁真相源；不得按文件时间自行覆盖、接管或绕过 canonical writer
- named mutex 获取或 runtime ladder 失败时停止后续写入，并按既有 `[writeback-fallback]` 路径重放

## 写回规则

- 用户明确开始、继续或切换并执行 write-authorized workflow 时：调用方读取实际 stage 后，用 `advance-stage.ps1 -ExpectedStage <actual> -SyncOnly -ActivateCurrent` 按单向链显式激活；继续 active task 不隐式切换 current。只读 status/review/inspect 不 replay、不 repair、不 sync/activate、不写 artifact/mirror/pointer/index，也不加载 stage skill
- mirror 始终同步实际 stage；background advance 不抢 current；active `DONE` 把 current 写为 canonical idle，background `DONE` 不改 current
- runtime ladder 首次失败即停止后续写入并返回非零；释放锁后向 `运行时/收件箱.md` 追加 open `[writeback-fallback]`。成功 `-SyncOnly` 在同 task stage mutex 内释放并按 `stage -> runtime` 顺序重取 runtime mutex，只清除匹配行，再释放 stage mutex
- write-authorized workflow 被打断、待续或等待反馈时：更新 `运行时\当前任务.md`（共享指针）+ `运行时\tasks\<task-id>.md`（详细状态）+ `运行时\中断任务.md`
- write-authorized workflow 的阶段完成并收尾时：更新 `运行时\上次会话.md`；必要时同步 `运行时\tasks\<task-id>.md` 的阶段结果或结束状态
- `当前任务.md` 或 task mirror 变化后：由 canonical writer 或 repair 刷新 `运行时\恢复索引.md`；legacy current-flow 不能覆盖已有 pointer
- 只有用户或外部来源已授权持久捕获 actionable/durable 新事项时，才可使用 `{REPO_ROOT}\scripts\append-runtime-inbox.ps1 -VaultRoot {VAULT_PATH} ...` 追加标准收件箱条目
- inbox task 由 entry-router 重新路由：从 `triage-runtime-inbox.ps1 -List` 的单行 JSON 读取 `open_items[].route_task_id` 作为唯一 task identity，并保留同项临时 `row_id`；`task_plan_exists=true` 走 `switch-existing`，否则进入 quick/workflow/ask。quick 交付与验证成功后立即用 `-RowId <row_id>` 精确 triage；workflow 仅在 canonical PLAN、validator 与 background `-SyncOnly` 成功后 triage；ask/pending 或失败保持 row open
- 需要人工选择时保持原 inbox row open 并直接向用户提问，不创建平行 decision 状态文件
- 可使用 `{REPO_ROOT}\scripts\triage-runtime-inbox.ps1 -VaultRoot {VAULT_PATH} -List` 获取单行 JSON，并用同项的 `-RowId <row_id> -SetStatus cleared` 精确关闭已处理条目；`route_task_id` 仅用于 workflow 路由
- 发现可能值得提升为长期记忆、但尚未确认的内容时：只向用户提示；只有用户明确要求记录/沉淀记忆后才写 `运行时\记忆候选.md`
- 只有用户明确请求或已授权的记忆维护任务，才把已完成提升、已否决或已清理的候选写入 `运行时\记忆候选归档.md`
- 只有已授权持久捕获的 actionable/durable 新事项才进入 `运行时\收件箱.md`；交互式归属或读写歧义先 ask，不写 inbox

## 禁写位置

- 不在 `MEMORY.md` 记录当前任务
- 不在 `配置\*.md` 记录会话级临时状态
- 不在 `配置\引导状态.md` 记录运行时任务
- 不在 agent 自己的 home 目录下写平行的 runtime note
- 不把 `恢复索引.md` 或 `中断任务.md` 当成比共享指针更强的独立真相源

## 长期记忆提升

- 只有跨项目、反复验证过的稳定偏好才允许提升
- 提升前需要用户确认
- 当前任务、中断任务、上次会话不提升为长期偏好
- 具体流程见 `{VAULT_PATH}\工作流\记忆管理协议.md`

## 兼容性优化

- 面向 agent 的关键入口文档优先使用普通 Markdown 结构，少依赖 Obsidian 专有语法
- 关键规则写明确文件名和路径，不只写 wiki link
- `恢复索引.md` 保持低 token、低成本，只做导航，不做独立判断
- 新增共享规则时，优先改这里，再让各 agent 的 skill 或入口文件引用这里
- schema 版本注册表见 `{VAULT_PATH}\配置\schema-versions.md`
- 敏感信息边界见 `{VAULT_PATH}\配置\敏感信息规范.md`
- 可通过 `{REPO_ROOT}\skills\obsidian-memory\scripts\check-shared-memory.ps1 -VaultRoot {VAULT_PATH}` 或 `{REPO_ROOT}\skills\obsidian-memory\scripts\run-memory-health.ps1 -VaultRoot {VAULT_PATH}` 定期检查共享记忆一致性
