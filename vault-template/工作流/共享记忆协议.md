# 共享记忆协议

## 范围与真相源

共享记忆仓库是 `{VAULT_PATH}`。它只承载已授权的稳定上下文，不是任务路由、协议选择或生命周期真相源。可选 Memory 只有安装且当前请求明确需要时才读取；写入还需要用户明确授权。

- 当前工作区规则与 Harness Runtime 优先于长期偏好。
- v2 任务状态由项目本地 `.assistant/runtime` 的原生 API 管理。
- `docs/tasks/{task_id}/` 保存任务产物与 Evidence，不以旧 plan frontmatter 驱动 v1 阶段。
- `配置/*.md` 与稳定的 `工作流/*.md` 不记录当前任务、指针或临时执行状态。
- 不在 `{CLAUDE_HOME}`、`{CODEX_HOME}` 或跨项目 Companion vault 中建立平行任务运行时。

## 任务入口与恢复

先遵循工作区的 Entry Contract。新任务只做 v2 准入与分类，不为查找旧任务而加载 Memory、旧收件箱、镜像或恢复索引。

只有明确的恢复或状态请求，且已选定 v2 协议后，才通过原生入口只读查看：

```powershell
pwsh -NoProfile -NonInteractive -File "{VAULT_PATH}\entry\task.ps1" status -AsJson
```

status 不重放、不修复、不激活指针。继续或切换任务必须有相应执行授权，并通过 v2 task API、Requirement Contract 和 Policy 执行。只有旧 plan 而没有 v2 state 的任务必须使用显式迁移维护，导入为 paused；Memory 不代替迁移。

`disable-v2` 暂停新工作，已有 v2 状态仍可恢复。禁止以 v1 fallback、旧 stage writer 或删除已迁移 state 作为止损。

## 稳定上下文

确有需要时按问题选择文件，而非每次任务全量加载：

- `工作流/项目约定.md`：项目级长期约定。
- `配置/用户偏好.md`：已确认的稳定偏好。
- `配置/工具与组件.md`：工具路径和组件说明，不推断当前安装健康。
- `配置/系统信息.md`：系统边界。
- `配置/敏感信息规范.md`：不向报告、日志或 Evidence 回显敏感值。

## 写入与隔离

- 普通 Inspect/status 为零写入；当前任务的临时选择不是长期偏好。
- 只有用户明确要求记录/沉淀记忆，才写 `运行时/记忆候选.md`；候选不是任务状态。
- 只有授权的记忆维护才提升、否决或归档候选，见 `工作流/记忆管理协议.md`。
- `运行时/收件箱.md` 只用于已授权持久捕获的业务事项。它不自动重放 v1 workflow、不选择协议、不创建任务。
- 交互式归属、读写或产品决定不清楚时，直接提问，保持零写入。
- hooks 保持只读；不得刷新 current、任务 state 或历史镜像。
- v2 写入只能通过对应原生 API 的版本、锁、授权与 CAS 校验；失败写入留在内部 failed-writes，不转成业务收件箱。

## 历史兼容维护

仓库保留的 v1 plan、镜像、`docs/shared-memory-layers.md` 与旧健康/修复工具仅供显式历史维护。它们不是普通 v2 安装或恢复依赖，不能自动修改当前 v2 状态。退役 stage writer 不再推进旧任务；历史迁移和物理删除各自需要明确授权。

不从 `MEMORY.md`、`配置/引导状态.md`、旧 `当前任务.md` 或 `恢复索引.md` 推断当前 v2 任务。长期记忆的管理不恢复旧生命周期。
