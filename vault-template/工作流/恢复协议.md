# 恢复协议

## 触发词
以下词句触发会话恢复流程：
- `继续` / `继续刚才的任务` / `刚才做到哪里了`
- `恢复` / `恢复一下`
- `continue` / `resume` / `what were we doing`

显式任务切换或新任务判断优先遵循 [[工作流/任务识别协议]]；本协议只处理已经确认要“恢复/继续已有任务”的场景。

## 读取顺序

1. 优先读取 [[运行时/恢复索引]]
2. **一致性检查**：比较 `恢复索引.md` 的 `updated` 时间戳与 `当前任务.md`、`中断任务.md`、`上次会话.md` 的 `updated` 时间戳
   - 如果任何源文件的 `updated` > 索引的 `updated` → 索引可能过期，先自动刷新索引再继续
   - 刷新后重新读取更新后的索引
3. 若索引信息不足，再读取 [[运行时/当前任务]]（共享指针）
4. 按共享指针中的 `task_id` 读取 `运行时/tasks/<task-id>.md`（任务级详细状态）
5. 然后读取 [[运行时/中断任务]]
6. 最后读取 [[运行时/上次会话]]
7. 如有命名检查点，再补充检查对应文件

## 恢复回复格式

恢复回复必须使用三段式结构，用分隔线 `---` 分隔：

### A. 当前主任务
```text
task: ...
progress: ...
next step: ...
```

### B. 其他中断任务（如有）
```text
task: ...
priority: ...
progress: ...
next step: ...
```

### C. 恢复选项
```text
1. 继续当前主任务
2. 切换到 [P1/P2] ...
3. 按编号切换到其他中断任务
```

## 规则

- 索引用于快速恢复，不替代运行时真相源
- 第一行先给主任务，不先讲背景
- 若 `当前任务.md` 与 `中断任务.md` 冲突，以 `当前任务.md` 为主
- 若 `中断任务.md` 的恢复选项与共享指针不一致，视为派生视图过期，优先提示入口 agent 刷新
- 若 `当前任务.md` 为空且 `上次会话.md` 标记未收尾，优先提示用户从中断任务继续
- 使用中文回复，除非用户明确要求切换语言
