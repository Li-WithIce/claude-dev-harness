# 写回协议

## 目标

让当前入口 host 在任务状态变化时稳定写回记忆，避免恢复锚点失真。

## 并行写保护

- 共享运行时文件（`当前任务.md`、`中断任务.md`、`上次会话.md`、`恢复索引.md`）只允许当前入口 host 写入；入口 host 由当前任务的 `entry_tool` 决定
- 若 Codex 不是当前入口 host，则只有用户明确开始、继续或切换并执行 write-authorized `mode=workflow` 时，才写任务工作区中的 `docs/tasks/{task_id}/*` artifact 和 `运行时/tasks/<task-id>.md`；read-only inspect/status 零写
- `advance-stage.ps1` 负责 canonical runtime 写回；Claude hooks 不写共享指针、task mirror 或恢复索引，避免与阶段推进竞争
- 共享运行时只通过 canonical writer / repair / 标准 inbox 脚本写入；这些入口内部使用同一 named mutex 串行化。`运行时/runtime.lock.json` 仅是 repair 期间的瞬时诊断文件，不是锁真相源，不得据此绕过或接管写入
- 并行任务各自写 `运行时/tasks/<task-id>.md`，不互相覆盖共享指针

## 写回规则

## 写回阶梯（单向链）

1. `docs/tasks/{task_id}/plan.md` frontmatter 是 stage 真相源。
2. 同步 `运行时/tasks/<task-id>.md` 详细状态。
3. task 已 active 或显式 `-ActivateCurrent` 时才刷新 `运行时/当前任务.md`；background task 跳过。
4. 刷新 `运行时/恢复索引.md` 派生导航视图。

- 步骤 2 / 3 / 4 首次失败即停止后续写入并返回非零；释放锁后向 `运行时/收件箱.md` 追加 open `[writeback-fallback]`。恢复先读该项，再以同一 `TaskId/ExpectedStage -SyncOnly` 重放；成功重放释放 runtime mutex 后，在仍持同 task stage mutex 时按 `stage -> runtime` 顺序重取 runtime mutex，只清除匹配项，最后释放 stage mutex。
- 反向写回一律禁止；详见 `docs/shared-memory-layers.md`（安装后完整路径：`{REPO_ROOT}\docs\shared-memory-layers.md`）。

### 0. 先做任务识别
在“开始任务 / 继续任务 / 切换任务”之前，先按 [[工作流/任务识别协议]] 判断本次请求属于 `resume-current`、`switch-existing`、`new-task` 还是 `inbox-first`。
若判定为 `new-task`，再按同一协议选择 `mode: quick | workflow | ask`；只有 `workflow` 需要创建 `docs/tasks/{task_id}/` 并刷新共享指针。
只读 status/review/inspect 只关联 identity 并读取必要文件，不 replay fallback、不执行 `SyncOnly` / `ActivateCurrent`、不写 artifact/mirror/pointer/index，也不加载 stage skill。

### 1. 开始任务
当用户明确开始、继续或切换并执行 write-authorized `mode=workflow` 时：
- 读取 `plan.md` 实际 stage，并通过 `advance-stage.ps1 -ExpectedStage <actual> -SyncOnly -ActivateCurrent` 更新 [[运行时/当前任务]] 与 task mirror；只读恢复/状态查询禁止调用
- `运行时/tasks/<task-id>.md` 至少记录 `schema_version`、`artifact_root`、`primary_artifact` 与 `artifact_links`
- 如有旧主任务未完成，先写入 [[运行时/中断任务]]
- **立即刷新 [[运行时/恢复索引]]**

### 2. 暂停或切换任务
当 write-authorized workflow 被打断、等待用户反馈、或主动切换时：
- 在 [[运行时/当前任务]] 记录当前 `task_id`、简短进度与下一步（共享指针）
- 在 `运行时/tasks/<task-id>.md` 记录已完成步骤、等待原因和下一步（详细状态）
- 在 [[运行时/中断任务]] 记录优先级、状态和下一步
- `中断任务.md` 中的恢复选项必须基于共享指针与任务状态文件重新生成，不手工维护独立真相
- **立即刷新 [[运行时/恢复索引]]**
- 切换到目标 task 时禁止手工改 current；对目标 task 执行 `-SyncOnly -ActivateCurrent`，且 `DONE` 不可激活

### 3. 收尾
当 write-authorized workflow 已完成可交付阶段时：
- 将摘要写入 [[运行时/上次会话]]
- 必要时更新 `运行时/tasks/<task-id>.md` 的阶段结果或结束状态
- active task 到 `DONE` 时由 canonical writer 把 [[运行时/当前任务]] 重置为 canonical idle；background `DONE` 不改 current
- **立即刷新 [[运行时/恢复索引]]**

### 4. 恢复索引刷新
当 `当前任务.md` 或 task mirror 被编辑后：
- 由 canonical writer 或 repair 立即刷新 [[运行时/恢复索引]]（上述规则 1-3 已内联此步骤，此条为兜底提醒）
- `恢复索引.md` 只保留当前主任务和合法未完成任务 Top N
- 不在索引中写入独立判断，只做低 token 导航

## 团队任务面板镜像

- team-mode 下，`team_task_update` 只在 vault 写回完成后由 leader 一次性 mirror
- team task-board 是 UI / orchestration 镜像，不改 vault 字段
- vault 永远是共享运行时的真相源

### 5. 已授权 durable 新事项进入
当用户或外部来源已授权持久捕获 actionable/durable 新事项、但暂时无法确定 task identity 时：
- 写入 [[运行时/收件箱]]；交互式归属或读写歧义直接 ask，不写 inbox
- 可使用 `{REPO_ROOT}\scripts\append-runtime-inbox.ps1 -VaultRoot {VAULT_PATH} -Type inbox-first ...` 追加标准条目
- 从 `triage-runtime-inbox.ps1 -List` 的单行 JSON 读取 `open_items[].route_task_id` 作为唯一 task identity，并保留同项临时 `row_id`；`task_plan_exists=true` 时走 `switch-existing`，否则用该 task ID 重新经过 entry-router 的 `new-task -> quick|workflow|ask`。quick 交付与验证成功后立即用 `-RowId <row_id>` 精确 triage；workflow 仅在 canonical PLAN、validator 与 background `-SyncOnly` 成功后 triage；ask/pending 或失败保持 open
- 需要人工选择时保持原 inbox row open 并直接向用户提问，不创建平行 decision 状态文件
- 可使用 `{REPO_ROOT}\scripts\triage-runtime-inbox.ps1 -VaultRoot {VAULT_PATH} -List` 获取单行 JSON，再按同项的 `row_id` 执行 `-RowId <row_id> -SetStatus cleared` 精确关闭；`route_task_id` 只决定 workflow task
- 再决定是否升级为当前任务或中断任务；read-only inspect/status 不创建 inbox row

### 6. 记忆候选记录
当观察到“可能值得提升为长期记忆、但尚未得到用户确认”的稳定模式时：
- 先向用户提示可沉淀内容；未获明确记忆写入授权时保持零写
- 只有用户明确要求记录/沉淀记忆后，才写入 [[运行时/记忆候选]]
- 不要直接写入 `配置/*.md`
- 待用户确认后，再按 [[工作流/记忆管理协议]] 提升

### 7. 记忆候选归档
当用户明确请求或已授权的记忆维护任务处理已提升、已否决或已失效候选时：
- 将简短记录移入 [[运行时/记忆候选归档]]
- 保持 `运行时/记忆候选.md` 低噪声

## 不应写入的位置
- `配置/引导状态.md` 不记录运行时任务
- `MEMORY.md` 不记录当前任务
- `配置/*.md` 不记录会话级临时状态
- `运行时/记忆候选.md` 不记录当前任务步骤
