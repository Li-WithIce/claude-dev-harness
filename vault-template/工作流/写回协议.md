# 写回协议

## 目标

让当前入口 host 在任务状态变化时稳定写回记忆，避免恢复锚点失真。

## 并行写保护

- 共享运行时文件（`当前任务.md`、`中断任务.md`、`上次会话.md`、`恢复索引.md`）只允许当前入口 host 写入；入口 host 由当前任务的 `entry_tool` 决定
- 若 Codex / Gemini 不是当前入口 host，则只写任务工作区中的 `docs/tasks/<task-id>/*` artifact 和 `运行时/tasks/<task-id>.md`
- 若 Claude 是当前入口 host，可依赖已部署的 Claude hooks 辅助刷新共享指针与 `恢复索引.md`；若 Codex / Gemini 是当前入口 host，则必须显式执行同等写回
- 写共享运行时前先检查 `运行时/runtime.lock.json`（锁超时：30 分钟未释放视为过期，可安全覆盖）；抢锁失败时将待写内容转入 `运行时/收件箱.md` 并标注 `[lock-blocked]`
- 并行任务各自写 `运行时/tasks/<task-id>.md`，不互相覆盖共享指针

## 写回规则

## 写回阶梯（单向链）

1. `docs/tasks/<task-id>/plan.md` frontmatter 是 stage 真相源。
2. 同步 `运行时/tasks/<task-id>.md` 详细状态。
3. 刷新 `运行时/当前任务.md` 共享指针。
4. 刷新 `运行时/恢复索引.md` 派生导航视图。

- 步骤 2 / 3 / 4 为 best-effort：失败时记 stderr，并向 `运行时/收件箱.md` 追加 `[writeback-fallback]`；不阻塞 `plan.md` 主推进。
- 反向写回一律禁止；详见 `{REPO_ROOT}\docs\shared-memory-layers.md`。

### 0. 先做任务识别
在“开始任务 / 继续任务 / 切换任务”之前，先按 [[工作流/任务识别协议]] 判断本次请求属于 `resume-current`、`switch-existing`、`new-task` 还是 `inbox-first`。
若判定为 `new-task`，再按同一协议选择 `mode: quick | workflow | ask`；只有 `workflow` 需要创建 `docs/tasks/<task-id>/` 并刷新共享指针。

### 1. 开始任务
当一个请求预计需要多步完成时：
- 更新 [[运行时/当前任务]]（共享指针）
- 更新 `运行时/tasks/<task-id>.md`（详细状态）
- `运行时/tasks/<task-id>.md` 至少记录 `schema_version`、`artifact_root`、`primary_artifact` 与 `artifact_links`
- 如有旧主任务未完成，先写入 [[运行时/中断任务]]
- **立即刷新 [[运行时/恢复索引]]**

### 2. 暂停或切换任务
当任务被打断、等待用户反馈、或主动切换时：
- 在 [[运行时/当前任务]] 记录当前 `task_id`、简短进度与下一步（共享指针）
- 在 `运行时/tasks/<task-id>.md` 记录已完成步骤、等待原因和下一步（详细状态）
- 在 [[运行时/中断任务]] 记录优先级、状态和下一步
- `中断任务.md` 中的恢复选项必须基于共享指针与任务状态文件重新生成，不手工维护独立真相
- **立即刷新 [[运行时/恢复索引]]**

### 3. 收尾
当一次会话已完成可交付阶段时：
- 将摘要写入 [[运行时/上次会话]]
- 必要时更新 `运行时/tasks/<task-id>.md` 的阶段结果或结束状态
- 如主任务已结束，清空或重置 [[运行时/当前任务]]
- **立即刷新 [[运行时/恢复索引]]**

### 4. 恢复索引刷新
当 `当前任务.md`、`中断任务.md`、`上次会话.md` 任一被编辑后：
- 立即刷新 [[运行时/恢复索引]]（上述规则 1-3 已内联此步骤，此条为兜底提醒）
- `恢复索引.md` 只保留当前主任务、Top 中断任务、上次会话短摘要
- 不在索引中写入独立判断，只做低 token 导航

## 团队任务面板镜像

- team-mode 下，`team_task_update` 只在 vault 写回完成后由 leader 一次性 mirror
- team task-board 是 UI / orchestration 镜像，不改 vault 字段
- vault 永远是共享运行时的真相源

### 5. 新事项进入
当收到尚未整理的新事项时：
- 先写入 [[运行时/收件箱]]
- 可使用 `{REPO_ROOT}\scripts\append-runtime-inbox.ps1 -VaultRoot {VAULT_PATH} -Type inbox-first ...` 追加标准条目
- 可使用 `{REPO_ROOT}\scripts\promote-runtime-inbox.ps1 -VaultRoot {VAULT_PATH} -Target interrupted-task ...` 或 `-Target decision-needed ...` 将 `inbox-first` 正式升级
- 可使用 `{REPO_ROOT}\scripts\triage-runtime-inbox.ps1 -VaultRoot {VAULT_PATH} -List` 列出 open 条目，再按 `-CreatedAt ... -SetStatus cleared` 正式关闭
- 再决定是否升级为当前任务或中断任务

### 6. 记忆候选记录
当观察到“可能值得提升为长期记忆、但尚未得到用户确认”的稳定模式时：
- 先写入 [[运行时/记忆候选]]
- 不要直接写入 `配置/*.md`
- 待用户确认后，再按 [[工作流/记忆管理协议]] 提升

### 7. 记忆候选归档
当候选项已提升、已否决、或已失效时：
- 将简短记录移入 [[运行时/记忆候选归档]]
- 保持 `运行时/记忆候选.md` 低噪声

## 不应写入的位置
- `配置/引导状态.md` 不记录运行时任务
- `MEMORY.md` 不记录当前任务
- `配置/*.md` 不记录会话级临时状态
- `运行时/记忆候选.md` 不记录当前任务步骤
